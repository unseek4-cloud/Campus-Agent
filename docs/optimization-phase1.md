# 第一批项目优化验收说明

> 前端已于 2026-10-13 合并为唯一 Vue 版本。本文中的旧静态入口与旧 Vue 组件路径为历史记录；当前启动、源码和测试命令见 [前端说明](../frontend/README.md) 与 [迁移记录](ui-vue-migration.md)。

日期：2026 年 10 月 12 日。主入口为 `frontend-standalone/` 新版前端；本批未修改 Vue 旧前端和项目方案书。

## 已完成

1. **申请材料逐项校验**：上传文件后可选择对应材料类别；缺少任一必交项不能提交。后端独立校验材料归属、文件与类别数量和必交项覆盖，不能靠篡改页面绕过。材料分类只说明文件对应哪项要求，内容是否合格仍由管理员审核。
2. **保存材料要求快照**：新申请保存提交时的材料 ID、名称、描述和必交标记。之后修改事项不改变已有申请的补交要求。附件详情及审核页面展示材料类别。
3. **固定分享范围**：整段分享在创建时展开为当时的消息 ID；继续聊天不会进入旧分享。标题采用创建时的快照，空会话不能生成链接。没有 ID 快照的历史整段链接只读取创建时间以前的消息；同一毫秒的边界消息保守排除，需要时重新生成链接。
4. **区分证据校验故障与知识缺失**：关闭重排时，知识库问答返回 `RERANK_UNAVAILABLE`，不再把配置问题表示为“未找到资料”。有召回内容但缺少全部重排分数时同样返回诊断异常。普通检索及数据库办事引导保留各自的行为。
5. **补充截止日期问法**：支持“报名截止？”“最晚哪一天？”“最后期限？”触发时间证据检查，并保留上一行的截止标题。此次没有实现相对日期计算或完整政策生效规则。
6. **新版表单细节**：切换事项清除原文件和分类；校验失败可继续修改；分类变化清除旧错误提示；补交前读取最新申请版本，减少旧列表版本引发的冲突。

## 数据库与接口

新增可重复执行的 `V10__application_materials.sql`，已注册到后端启动初始化列表并打入更新后的 JAR。

- `service_application_material`：每份新申请的材料要求快照。
- `service_application_attachment_material`：附件与材料项的关联。

迁移只新增表，不删除或改写已有申请、附件及事项。历史附件没有分类时按原方式显示，历史申请没有快照时继续支持普通补交，不从当前事项反推历史要求。

创建与补交接口在原 multipart 字段之外支持重复字段 `materialIds`，顺序对应重复字段 `files`。空字符串代表其他附件；非空 ID 必须属于该申请的材料范围。创建时所有必交 ID 都必须至少关联一份文件。对于没有必交材料的事项，旧的无分类文件请求仍然可用。

申请详情新增 `materials[]`；附件新增 `materialId` 和 `materialName`，未分类时为 null。旧 Vue 前端未加入分类选择，因此有必交材料的事项请使用新版入口。

## 运行和手动验收

本机后端 JAR 已重新打包。重启正在运行的 Java 后端和 AI 服务，再用 Ctrl+F5 刷新版页面；Java 启动时会执行新增迁移。若之后继续修改 Java 源码，需要重新构建，已有启动脚本默认复用 JAR，不能只重启旧包。

建议按以下顺序核对：

1. 新版前端登录学生账号，对一个有两项必交材料的事项发起申请。只上传并分类其中一项应提示缺少另一项；分类齐全后提交成功。
2. 管理员查看附件，能看到“对应材料”；要求补交后修改当前事项的材料清单，学生补交仍应显示原申请的要求。
3. 分享一段已有消息的会话，再继续聊天；旧链接不应出现新消息，新建整段分享才包含新范围。
4. 测试“报名截止？”与“最晚哪一天？”；检查时间证据处理是否触发。最终答案还需结合学校真实语料验证。
5. 临时关闭重排验证明确故障提示，然后恢复原配置；不要把该配置作为问答降级方案。

自动重跑：在 `ai-service/` 执行 `.venv/Scripts/python.exe -m pytest -q`；在 `backend/` 执行 `mvn test`；根目录执行 `node frontend-standalone/tests/application-materials.e2e.mjs` 与 `node frontend-standalone/tests/chat-workspace.e2e.mjs`。浏览器脚本默认复用现有 Playwright Core 和 Edge，可通过 `PLAYWRIGHT_MODULE_PATH` 与 `BROWSER_EXECUTABLE` 指向已安装工具。

此次 Maven 验证显式使用了本机已有的 `.m2/repository` 缓存位置，避免执行环境选择到另一个空缓存；没有下载新依赖或修改项目依赖版本。验证日志与截图保存在忽略的 `tmp/`，不进入提交源码。
